# Manifiesto Conceptual: Aparato `i18n.ts`

## 1. Rol Estratégico y Propósito

Este aparato es el **motor de la arquitectura IMAS (I18n Mirrored Atomic Structure)**. Su única y crítica responsabilidad es orquestar la carga y el ensamblaje de todos los módulos de mensajes de traducción atómicos para una petición específica. Actúa como el punto de configuración central para `next-intl` en el lado del servidor.

Su propósito es transformar una colección de archivos de mensajes desacoplados en el único objeto anidado que `next-intl` espera, permitiendo que el resto de la aplicación opere con una API de i18n cohesiva sin conocer los detalles de la estructura de archivos.

## 2. Arquitectura y Flujo de Ejecución

El flujo de ejecución implementa el patrón de "carga dinámica basada en manifiesto".

```mermaid
graph TD
    A[Petición Entrante con `locale`] --> B["`getRequestConfig` (i18n.ts)"];
    B -- "Inicia bucle sobre" --> C["`messages/manifest.ts`"];
    C -- "Para cada namespace" --> D["Invoca `moduleLoader()` (import dinámico)"];
    D -- "Carga" --> E["Archivo JSON Atómico (ej. `OrderForm.json`)"];
    E -- "Extrae traducciones para el `locale`" --> F;
    F -- "Usa `setNestedProperty` para ensamblar en" --> G[Objeto `messages` anidado];
    G -- "Es retornado a" --> H["`next-intl`"];
    H -- "Provee traducciones a" --> I["Server/Client Components"];
Esta arquitectura es altamente performante y escalable, ya que los módulos de mensajes se cargan bajo demanda.
3. Contrato de API
Exportación por Defecto: export default getRequestConfig(...)
Lógica Interna: Devuelve una función asíncrona que, dado un locale, retorna una configuración para next-intl que incluye un objeto messages completamente ensamblado y anidado, listo para ser consumido por la aplicación.
4. Zona de Melhorias Futuras
VALIDACIÓN DE SCHEMAS EN DESARROLLO: En modo de desarrollo, el orquestador podría importar dinámicamente no solo el JSON, sino también un schema Zod correspondiente (src/lib/validators/i18n/...) y validarlo, proporcionando feedback inmediato sobre inconsistencias entre el contrato y el contenido.
FALLBACKS DE NAMESPACE: Si un namespace no tiene traducciones para el locale actual, la lógica podría intentar cargar las traducciones del defaultLocale para ese namespace específico, aumentando la resiliencia del sistema.
REPORTE DE CLAVES FALTANTES: Generar un reporte durante el build que liste los namespaces que no tienen traducciones para todos los locales soportados, facilitando la gestión de la traducción.
CACHEADO DE MÓDULOS: Investigar el uso de React.cache para cachear los módulos de mensajes ya importados entre renderizados de Server Components dentro de la misma petición, optimizando aún más el rendimiento.
ABSTRACCIÓN DEL ENSAMBLADOR: La lógica del bucle for y setNestedProperty podría ser extraída a un helper assembleMessages(manifest, locale) para mantener i18n.ts más declarativo.
