# Manifiesto Conceptual: Aparato `i18n.ts`

## 1. Rol Estratégico y Propósito

Este aparato es el **motor de la arquitectura IMAS (I18n Mirrored Atomic Structure)**. Su propósito es orquestar la carga y el ensamblaje de todos los módulos de mensajes de traducción atómicos para una petición específica.

Actúa como un orquestador de alto nivel que delega la lógica de ensamblaje a un helper atómico, transformando una colección de archivos desacoplados en el único objeto anidado que `next-intl` espera.

## 2. Arquitectura y Flujo de Ejecución

El flujo sigue un patrón de "Orquestador / Ensamblador Atómico".

```mermaid
graph TD
    A[Petición Entrante con `locale`] --> B["`getRequestConfig` (i18n.ts)"];
    B -- "Valida `locale` y delega a" --> C["`assembleMessagesFromManifest`"];
    C -- "Lee" --> D["`messages/manifest.ts`"];
    D -- "Inicia bucle de carga para cada namespace" --> E["Import() dinámico"];
    E --> F["Archivo JSON Atómico"];
    F -- "Extrae traducciones (con lógica de fallback)" --> G;
    G -- "Usa `setNestedProperty` para ensamblar" --> H[Objeto `messages` anidado];
    H -- "Retorna a" --> C;
    C -- "Retorna a" --> B;
    B -- "Provee a" --> I["`next-intl`"];
Esta arquitectura es performante, resiliente y altamente mantenible.
3. Contrato de API
Exportación por Defecto: export default getRequestConfig(...)
Lógica Interna: Devuelve una función asíncrona que, dado un locale, retorna una configuración para next-intl que incluye un objeto messages completamente ensamblado y anidado.
4. Zona de Melhorias Futuras
VALIDACIÓN DE SCHEMAS EN DESARROLLO: En modo de desarrollo, el ensamblador podría importar un schema Zod correspondiente a cada namespace y validar el contenido del JSON, proporcionando feedback inmediato sobre inconsistencias entre el contrato y el contenido.
INTEGRACIÓN CON TMS (Translation Management System): El ensamblador podría ser extendido para, en producción, obtener los mensajes desde una API de un TMS en lugar del sistema de archivos, permitiendo actualizaciones de texto sin necesidad de un deploy.
REPORTE DE CLAVES FALTANTES: Generar un reporte durante el build que liste los namespaces que no tienen traducciones para todos los locales soportados, facilitando la gestión del proceso de traducción.
MODO DEBUG DE I18N: Implementar una lógica que, activada por una cookie o query param, envuelva todas las strings traducidas en la UI con caracteres especiales para identificar fácilmente qué textos provienen de la capa de i18n y cuáles están hardcodeados.
