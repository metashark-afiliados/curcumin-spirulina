# Manifiesto Conceptual: Orquestador `i18n.ts` (Server-Side)

## 1. Rol Estratégico y Propósito

Este aparato es el **cerebro de la internacionalización en el lado del servidor**. Su única responsabilidad es actuar como una **función pura** que ensambla y provee el objeto de mensajes de traducción a `next-intl` para una petición y `locale` específicos.

**NOTA ARQUITECTÓNICA CRÍTICA:** Este módulo ha sido despojado deliberadamente de cualquier efecto secundario, incluyendo el logging transaccional. Su interacción con el ciclo de vida interno de `next-intl` y el motor de renderizado de Next.js requiere que se comporte como una utilidad de configuración pura para prevenir errores de runtime (`TypeError: Invalid value used as weak map key`). La observabilidad de su ejecución se infiere a partir de los logs de los componentes que lo consumen (ej. `HomePage`).

## 2. Arquitectura y Flujo de Ejecución

Es un módulo de configuración que se integra con el ciclo de vida de `next-intl`, actuando como una factoría de mensajes.

3. Contrato de API
default getRequestConfig({ locale }): La función principal que next-intl consume para obtener los mensajes de un locale específico.
4. Zona de Mejoras Nuevas (Valor al Proyecto)
Validación de Módulos con Zod (Build-Time): Implementar un script que, en tiempo de build, valide la estructura de cada módulo de mensajes cargado.
Gestión de Fallback a Nivel de Mensaje: Extender la lógica para que, si un namespace no tiene traducciones, intente cargar su versión del defaultLocale.
Cacheo de Traducciones (React.cache): Implementar una estrategia de caché para evitar la recarga de módulos de mensajes que no han cambiado, mejorando el rendimiento.
